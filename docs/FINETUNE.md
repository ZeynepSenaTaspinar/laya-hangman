# Fine-tuning Laya for Hangman

The stock `convaiinnovations/laya` checkpoint is not trained for this task and played 0/20 games (see the README).
Laya's own docs say fine-tuning is where most of the value is. This repo ships a ready training set and the exact commands.
**Nothing here has been trained yet, so no result is claimed.** Training needs a GPU; an Intel Mac is not practical.

## What the training data is (read this before you use or cite a result)

`data/train.jsonl.gz` (11,292 rows) is generated by `python -m laya_hangman.training_data`:

* Each row is a partial game state, in exactly the format the app sends to Laya at play time (`state` text plus the same `choice` question
  with the unguessed letters as options).
* The label (`gold`) is a **teacher's** soft distribution over the unguessed letters: for every letter, how many dictionary words that are
  still consistent with the visible state contain it, sharpened with exponent 3 and normalised. The teacher dictionary is the public-domain
  ENABLE list (151,105 words of 4-12 letters, sha256 in `data/train.jsonl.manifest.json`) plus this repo's word list.
* **Leave-one-out:** the secret word is removed from the candidates when its own states are labelled, so a label never encodes the secret's letters.
* **No evaluation leakage:** the 232 evaluation words are removed from the teacher dictionary and are never used as training secrets (asserted when
  the data is built, and tested). Training secrets are the 834 dev words (10 states each) plus 3,000 random ENABLE words (4 states each). States are
  sampled from games played by a mix of random, noisy-frequency and noisy-greedy policies.
* **At play time nothing changes:** Laya still gets only the visible state and answers in one forward pass. There is no dictionary, candidate list or
  answer in any inference request. But a fine-tuned Laya has *learned letter statistics from a dictionary teacher*, so it is fair to describe it as a
  distilled model, not as a model that "figured Hangman out" by itself.

Regenerate it (about 7 minutes, downloads ENABLE): `python -m laya_hangman.training_data --out train.jsonl`.

## Train on a free GPU (Kaggle or Colab)

1. Get `data/train.jsonl.gz` from this repo onto your computer, then upload it to Kaggle (new Notebook, **Accelerator: GPU T4**, **Internet: On**, add the file as a dataset) or to Colab (GPU runtime, upload the file).
2. Run, in notebook cells (prefix with `!`) or a terminal:

```bash
pip install -q laya==0.4.6
gunzip -kf train.jsonl.gz
# check the data against the real tokenizer first (no training, no weights):
laya-train --data train.jsonl --base english --max-len 512 --head-max-len 192 --dry-run
# train (default recipe: 4 epochs, effective batch 64):
laya-train --data train.jsonl --base english --out ./laya-hangman-ft \
           --loss soft-ce --shuffle-options --epochs 4 --max-len 512 --head-max-len 192
```

`--dry-run` must report zero skipped rows (in particular no `options_collapsed`). `--shuffle-options` re-orders the 25-26 letter options every epoch, which
Laya's docs report helps with many options. Expect a run of very roughly an hour on a T4 (**an estimate, not measured**). If the run stalls at chance,
see "Diagnose a run that stays at chance" in Laya's `docs/finetune.md` (try another `--seed`, more `--epochs`).

3. Download the output folder `laya-hangman-ft` (about 1-2 GB) to your Mac.

## Use and evaluate the fine-tuned model

```bash
LAYA_MODEL=/path/to/laya-hangman-ft .venv/bin/python -m laya_hangman             # the app
LAYA_MODEL=/path/to/laya-hangman-ft .venv/bin/python -m laya_hangman.evaluate \
    --split eval --deciders baseline laya --limit 40 --progress                   # official rules: 6 incorrect guesses
```

The evaluation words were never seen in training. Hangman with only 6 wrong guesses is very hard on 5-7-letter words (this repo's list is mostly that), so win rate is coarse;
the report also gives `Mean revealed` (share of the word uncovered). For a supplementary, less saturated comparison add `--max-incorrect 10` (not the game's rule; report it as such).
Compare against the baseline under identical settings, and do not tune on the evaluation split: if you change anything (sharpen, epochs, data), select on `--split dev`.
